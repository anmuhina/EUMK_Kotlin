Раздел 3. Работа с данными и сетью (Room, Retrofit, корутины)

3.1. Архитектура Android-приложения (MVVM + Clean Architecture)

Современное Android-приложение строится по паттерну MVVM (Model–View–ViewModel) с элементами Clean Architecture. Слои:

  • UI (View) — Compose-экраны, наблюдают за состоянием ViewModel;
  • ViewModel — хранит UI-состояние, вызывает репозиторий, переживает смену конфигурации;
  • Repository — единый источник данных, комбинирует сеть и кэш (БД);
  • Data sources — Retrofit (сеть) и Room (локальная БД).

Такое разделение обеспечивает тестируемость, переиспользуемость и независимость бизнес-логики от UI. ViewModel во фреймворке Android предоставляется библиотекой androidx.lifecycle:lifecycle-viewmodel-compose.

class UserViewModel(private val repo: UserRepository) : ViewModel() {
    private val _state = MutableStateFlow<UiState>(UiState.Loading)
    val state: StateFlow<UiState> = _state.asStateFlow()

    fun load(id: String) = viewModelScope.launch {
        _state.value = UiState.Loading
        _state.value = runCatching { repo.getUser(id) }
            .fold({ UiState.Success(it) }, { UiState.Error(it.message ?: "Ошибка") })
    }
}

3.2. Корутины Kotlin

Корутина — легковесный поток выполнения, управляемый планировщиком Kotlin. В отличие от потоков ОС, корутины не блокируют поток при приостановке (suspend), а освобождают его для других задач. Это позволяет запускать тысячи корутин без накладных расходов на потоки.

Ключевые понятия:

  • suspend-функция — функция, которая может приостанавливать выполнение, не блокируя поток; вызывается только из корутины или другой suspend-функции;
  • CoroutineScope — область жизни корутин; при отмене scope отменяются все его корутины;
  • Dispatchers — планировщики: Main (UI), IO (сеть/диск), Default (CPU-задачи), Unconfined;
  • launch — запуск корутины без результата; async — с результатом (Deferred, ожидается через await);
  • withContext(Dispatchers.IO) — переключение контекста внутри suspend-функции.
suspend fun loadUsers(): List<User> = withContext(Dispatchers.IO) {
    api.getUsers()   // сетевой вызов
}

Структурная конкурентность: корутины всегда привязаны к scope, и родительская корутина ждёт завершения дочерних. viewModelScope автоматически отменяется при уничтожении ViewModel; lifecycleScope — при уничтожении Activity/Fragment. GlobalScope использовать не рекомендуется.

Обработка ошибок: try/catch внутри корутины, CoroutineExceptionHandler для launch, runCatching/Result для функционального стиля. Отмена корутины — через CancellationException и проверку isActive/ensureActive().

3.3. Потоки данных: Flow, StateFlow, SharedFlow

Flow — холодный асинхронный поток данных (аналог Sequence, но с поддержкой suspend). Создаётся через flow { emit(...) } или из коллекций (asFlow()). Операторы: map, filter, flatMapLatest, catch, onEach, debounce:

fun usersFlow(): Flow<List<User>> = flow {
    emit(api.getUsers())
}.catch { emit(emptyList()) }

StateFlow — горячий поток с текущим значением (аналог LiveData); всегда имеет начальное состояние, эмитит последнее значение новым подписчикам. Используется для UI-состояния.

SharedFlow — горячий поток без начального значения; применяется для событий (например, навигация, snackbar).

В Compose Flow собирается через collectAsStateWithLifecycle():

val state by viewModel.state.collectAsStateWithLifecycle()

3.4. Room: локальная база данных

Room — ORM-библиотека над SQLite, часть Jetpack. Она проверяет SQL-запросы на этапе компиляции, поддерживает Flow в запросах (автоматическое обновление при изменениях), suspend-методы и транзакции. Room избавляет от ручного написания Cursor-кода и снижает вероятность ошибок. Компоненты:

  • @Entity — таблица; поля класса = столбцы;
  • @Dao — интерфейс с методами доступа к данным (аннотации @Insert, @Update, @Delete, @Query);
  • @Database — абстрактный класс, связывающий сущности и DAO.
@Entity(tableName = "notes")
data class Note(
    @PrimaryKey(autoGenerate = true) val id: Long = 0,
    val title: String,
    val content: String,
    val createdAt: Long = System.currentTimeMillis()
)

@Dao
interface NoteDao {
    @Insert(onConflict = OnConflictStrategy.REPLACE)
    suspend fun upsert(note: Note): Long

    @Query("SELECT * FROM notes ORDER BY createdAt DESC")
    fun observeAll(): Flow<List<Note>>

    @Delete
    suspend fun delete(note: Note)
}

@Database(entities = [Note::class], version = 1, exportSchema = false)
abstract class AppDatabase : RoomDatabase() {
    abstract fun noteDao(): NoteDao

    companion object {
        @Volatile private var INSTANCE: AppDatabase? = null
        fun get(context: Context): AppDatabase =
            INSTANCE ?: synchronized(this) {
                INSTANCE ?: Room.databaseBuilder(context, AppDatabase::class.java, "app.db")
                    .fallbackToDestructiveMigration()
                    .build().also { INSTANCE = it }
            }
    }
}

Room поддерживает Flow в запросах (автоматическое обновление при изменениях), suspend-методы, транзакции (@Transaction), отношения (@Relation), миграции. Использование Room исключает ошибки SQL на этапе компиляции благодаря проверке запросов.

3.5. Retrofit: сетевые запросы

Retrofit — типобезопасный HTTP-клиент для Android/JVM, построенный поверх OkHttp. API описывается интерфейсом с аннотациями, а Retrofit генерирует реализацию. Это позволяет вызывать REST-эндпоинты как обычные функции Kotlin.

Аннотации: @GET, @POST, @PUT, @DELETE, @PATCH задают HTTP-метод и путь; @Path подставляет значение в URL; @Query добавляет query-параметр; @Body задаёт тело запроса; @Header/@Headers — заголовки; @FormUrlEncoded/@Field — form-data.

data class UserDto(
    val id: Int,
    val name: String,
    val email: String,
    @SerialName("phone") val phoneNumber: String? = null
)

interface ApiService {
    @GET("users")
    suspend fun getUsers(): List<UserDto>

    @GET("users/{id}")
    suspend fun getUser(@Path("id") id: Int): UserDto

    @POST("posts")
    suspend fun createPost(@Body post: PostDto): PostDto

    @GET("search")
    suspend fun search(@Query("q") query: String, @Query("page") page: Int = 1): List<UserDto>
}

Настройка клиента:

val retrofit = Retrofit.Builder()
    .baseUrl("https://jsonplaceholder.typicode.com/")
    .addConverterFactory(Json { ignoreUnknownKeys = true }
        .asConverterFactory("application/json".toMediaType()))
    .client(OkHttpClient.Builder()
        .addInterceptor(HttpLoggingInterceptor().apply { level = HttpLoggingInterceptor.Level.BODY })
        .connectTimeout(30, TimeUnit.SECONDS)
        .build())
    .build()

val api = retrofit.create(ApiService::class.java)

3.6. Паттерн Repository и кэширование

Репозиторий скрывает источники данных от ViewModel и реализует стратегию «сеть с кэшем в БД»:

class UserRepository(
    private val api: ApiService,
    private val dao: UserDao
) {
    fun observeUsers(): Flow<List<User>> = dao.observeAll()

    suspend fun refresh(): Result<Unit> = runCatching {
        val remote = api.getUsers().map { it.toEntity() }
        dao.replaceAll(remote)
    }
}

Такой подход обеспечивает работу offline: UI читает из БД (Flow обновляется автоматически), а сеть лишь синхронизирует данные.

3.7. Обработка ошибок и состояний загрузки

UI-состояние принято моделировать sealed-классом:

sealed interface UiState<out T> {
    data object Loading : UiState<Nothing>
    data class Success<T>(val data: T) : UiState<T>
    data class Error(val message: String) : UiState<Nothing>
}

Это позволяет исчерпывающе обрабатывать состояния через when и не забывать про ветки ошибок и загрузки.
